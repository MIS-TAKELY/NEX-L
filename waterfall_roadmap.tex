
\subsection{Development Roadmap -- Waterfall Model}

The NEXL platform was developed following a structured \textbf{Waterfall Software Development Life Cycle (SDLC)}, where each phase was fully completed and signed off before advancing to the next. This linear, sequential approach ensured thorough documentation, clear traceability of requirements, and disciplined delivery at each stage of the project lifecycle.

% -------------------------------------------------------
\subsubsection*{Phase 1: Requirements Analysis \hfill \textit{(Completed)}}

\textbf{Objective:} Gather, document, and formally approve all functional and non-functional requirements before any design or development activity commenced.

In this phase, the team conducted stakeholder interviews, reviewed similar e-learning platforms, and studied the technical and infrastructural constraints specific to the Nepali broadband environment. The resulting requirements specification served as the authoritative reference document for all subsequent phases.

\textbf{Key Outcomes:}
\begin{itemize}
    \item Defined multi-role system access requirements for three distinct user types: \textbf{Student}, \textbf{Instructor}, and \textbf{Administrator}.
    \item Identified and documented multi-modal content delivery requirements, encompassing \textbf{video}, \textbf{quiz}, and \textbf{assignment}-based learning formats.
    \item Specified payment processing requirements, including support for \textbf{NPR-based transactions} via the eSewa payment gateway.
    \item Established performance benchmarks and latency targets suited to typical \textbf{Nepali broadband conditions}.
    \item Documented requirements for \textbf{AI-assisted metadata generation}, media storage via Cloudinary, and real-time communication capabilities.
    \item Defined \textbf{gamification requirements} including a digital badge and progress incentive system.
\end{itemize}

% -------------------------------------------------------
\subsubsection*{Phase 2: System Design \hfill \textit{(Completed)}}

\textbf{Objective:} Translate the approved requirements into a comprehensive technical architecture covering both the frontend and backend systems.

The design phase produced all architectural blueprints, database schemas, API contracts, and UI wireframes required to guide the implementation team. No development began until all design artifacts were reviewed and approved.

\textbf{Key Outcomes:}
\begin{itemize}
    \item \textbf{Frontend Architecture:} Designed the component hierarchy and page flow structure for a \textbf{React} and \textbf{Vite} application, styled with \textbf{Tailwind CSS}, covering all user roles and interaction patterns.
    \item \textbf{Backend Architecture:} Designed a RESTful API structure using \textbf{Node.js} and \textbf{Express.js}, with \textbf{MongoDB} selected as the primary data store.
    \item \textbf{Security Design:} Defined the authentication and authorization architecture using \texttt{better-auth} with \textbf{JWT} tokens and \texttt{bcrypt} password hashing; specified a role-based access control (RBAC) model.
    \item \textbf{Database Schema:} Finalized collections and entity relationships for \textit{Users}, \textit{Courses}, \textit{Quizzes}, \textit{Assignments}, \textit{Badges}, and \textit{Payments}.
    \item \textbf{Media Pipeline Design:} Architected the \textbf{Cloudinary} integration for media upload, storage, transformation, and delivery.
    \item \textbf{Third-Party Integration Design:} Documented integration contracts for the \textbf{Stream SDK} (live streaming and chat), \textbf{Hugging Face Inference API} (AI metadata), and \textbf{eSewa} (payment gateway).
\end{itemize}

% -------------------------------------------------------
\subsubsection*{Phase 3: Implementation \hfill \textit{(Completed)}}

\textbf{Objective:} Translate all approved design artifacts into functional, production-ready source code across the frontend and backend.

Implementation proceeded in strict adherence to the design specifications produced in Phase 2. The development was organized into two parallel workstreams: frontend and backend, coordinated to ensure interface contracts were consistently met.

\paragraph{Frontend Implementation}
\begin{itemize}
    \item \textbf{Platform Core:} Developed the \textbf{landing page} with platform branding and feature introduction, and implemented \textbf{course search and discovery} with advanced filtering. A secure \textbf{RBAC routing system} was enforced across all user roles.
    \item \textbf{Learning Interfaces:} Built dedicated \textbf{content players} for video streaming, interactive quiz completion, and assignment submission, each tailored to their respective modality.
    \item \textbf{Communication Features:} Integrated the \textbf{Stream SDK} to deliver live class streaming and real-time chat functionality within the platform.
    \item \textbf{E-Commerce:} Implemented the complete \textbf{cart management system}, promotional \textbf{coupon and discount logic}, and end-to-end \textbf{payment checkout flows}.
\end{itemize}

\paragraph{Backend Implementation}
\begin{itemize}
    \item \textbf{Security \& Identity:} Implemented robust user authentication using \texttt{better-auth} and \textbf{JWT}; enforced secure password storage via \texttt{bcrypt} hashing.
    \item \textbf{Course Engine:} Delivered full \textbf{CRUD operations} for course, module, and lesson management; integrated the \textbf{Hugging Face Inference API} for automated AI-assisted generation of course metadata.
    \item \textbf{Assessment \& Gamification:} Developed functional \textbf{quiz} and \textbf{assignment} modules with grading logic, and implemented an \textbf{automated digital badge system} to reward student progress milestones.
    \item \textbf{Media \& Payments:} Configured \textbf{Cloudinary} for all media upload and delivery operations; implemented the \textbf{eSewa} payment gateway integration for NPR-based course purchases.
\end{itemize}

% -------------------------------------------------------
\subsubsection*{Phase 4: Testing \& Integration \hfill \textit{(In Progress)}}

\textbf{Objective:} Systematically verify that all implemented modules conform to the documented requirements and function correctly as an integrated system.

This phase is currently the primary focus of the development team. Testing is performed against the requirements specification from Phase 1, and all defects discovered are tracked and resolved before sign-off.

\textbf{Ongoing Activities:}
\begin{itemize}
    \item \textbf{Unit Testing:} Validating individual API endpoints, frontend React components, and isolated backend business logic functions.
    \item \textbf{Integration Testing:} Verifying correct end-to-end interaction between the frontend, backend, \textbf{Cloudinary}, \textbf{Stream SDK}, \textbf{Hugging Face API}, and \textbf{eSewa} gateway.
    \item \textbf{Performance Testing:} Profiling and optimizing database query execution times and AI inference response latency to meet the benchmarks defined in Phase 1 under typical Nepali broadband conditions.
    \item \textbf{Cross-Platform Testing:} Validating UI responsiveness and layout integrity across desktop, tablet, and mobile viewports.
    \item \textbf{Security Auditing:} Reviewing all authentication flows, authorization middleware, and API endpoints for potential vulnerabilities and unauthorized data exposure.
\end{itemize}

% -------------------------------------------------------
\subsubsection*{Phase 5: Deployment \hfill \textit{(Planned)}}

\textbf{Objective:} Release the fully tested and approved system to a production cloud environment, making the NEXL platform publicly accessible.

Deployment will only commence upon formal sign-off from the testing phase, in accordance with the Waterfall model's sequential gate process.

\textbf{Planned Activities:}
\begin{itemize}
    \item Provisioning of \textbf{cloud hosting infrastructure}, including server setup, environment variable configuration, and domain name assignment.
    \item Configuration of a \textbf{CI/CD pipeline} for automated, reproducible future deployments.
    \item Execution of database \textbf{migrations and initial data seeding} for production readiness.
    \item Setup of \textbf{SSL/TLS certificates} and a reverse proxy (e.g., \textbf{Nginx}) for secure HTTPS traffic routing.
    \item Post-deployment \textbf{smoke testing} and end-to-end validation to confirm production system stability.
\end{itemize}

% -------------------------------------------------------
\subsubsection*{Phase 6: Maintenance \hfill \textit{(Planned -- Post-Deployment)}}

\textbf{Objective:} Ensure the long-term health, security, and performance of the live NEXL platform through continuous monitoring and iterative improvement.

\textbf{Planned Activities:}
\begin{itemize}
    \item Continuous \textbf{system health and uptime monitoring} using server-side logging and alerting tools.
    \item Triaging and resolving \textbf{production bugs} and incidents reported via user feedback channels.
    \item Applying \textbf{security patches} and upgrading third-party dependencies as new vulnerabilities are disclosed.
    \item Iterative \textbf{performance optimization} of backend services and frontend assets as user load increases.
\end{itemize}
