
\chapter{Implementation and Testing}

This chapter presents the complete implementation and testing lifecycle of the NEXL platform. It covers the tools and technologies employed during development, a detailed description of the core modules and their underlying logic, and the testing strategies used to validate functional correctness and system-wide reliability.

% =======================================================
\section{Implementation}

The NEXL platform was implemented as a full-stack web application, with a client-facing frontend and a RESTful backend API. The implementation followed the architectural specifications defined during the design phase, ensuring consistency between design intent and the delivered system.

% -------------------------------------------------------
\subsection{Tools Used}

\subsubsection{CASE Tools}
The following Computer-Aided Software Engineering (CASE) tools were used throughout the development lifecycle:

\begin{itemize}employed
    \item \textbf{Visual Studio Code} -- Primary code editor used for both frontend and backend development, with extensions for ESLint, Prettier, and Tailwind CSS IntelliSense.
    \item \textbf{Postman} -- Used for designing, testing, and documenting REST API endpoints during backend development.
    \item \textbf{MongoDB Compass} -- GUI-based tool for inspecting, querying, and managing MongoDB collections during development and debugging.
    \item \textbf{Git \& GitHub} -- Version control system used for source code management, branching, and team collaboration.
    \item \textbf{Figma} -- Used for UI/UX wireframing and prototyping prior to frontend implementation.
    \item \textbf{draw.io} -- Used for creating system architecture diagrams, ER diagrams, and data flow diagrams.

\subsubsection{Programming Languages}
\begin{itemize}
    \item \textbf{JavaScript (ES2022+)} -- The primary programming language used across the full stack, enabling code consistency between the frontend and backend.
    \item \textbf{JSX} -- A JavaScript syntax extension used within React components to declaratively describe the user interface.
    \item \textbf{HTML5} -- Used for semantic document structure within React components.
    \item \textbf{CSS3} -- Used for custom styling in combination with the Tailwind CSS utility framework.
\end{itemize}

\subsubsection{Frameworks and Libraries}
\begin{itemize}
    \item \textbf{React.js} -- Component-based frontend library used to build the interactive user interface.
    \item \textbf{Vite} -- Fast frontend build tool and development server used to scaffold and bundle the React application.
    \item \textbf{Tailwind CSS} -- Utility-first CSS framework used to implement a responsive and consistent design system.
    \item \textbf{Node.js} -- JavaScript runtime environment used to execute the backend server-side application.
    \item \textbf{Express.js} -- Minimal and flexible Node.js web framework used to define RESTful API routes, middleware, and controllers.
    \item \textbf{better-auth} -- Authentication library used to manage session handling and user identity.
    \item \textbf{bcrypt} -- Library used for secure, salted password hashing before storage in the database.
    \item \textbf{jsonwebtoken (JWT)} -- Used for generating and verifying JSON Web Tokens for stateless session management.
    \item \textbf{Stream SDK} -- Used to integrate live-streaming and real-time chat features into the platform.
    \item \textbf{Hugging Face Inference API} -- External AI API used for automated course metadata generation.
    \item \textbf{Multer / Cloudinary SDK} -- Used for handling file uploads and storing media assets on Cloudinary's CDN.
\end{itemize}

\subsubsection{Database Platforms}
\begin{itemize}
    \item \textbf{MongoDB} -- NoSQL document-oriented database used as the primary data store for all platform entities including users, courses, quizzes, assignments, badges, and transactions.
    \item \textbf{Mongoose} -- Object Data Modelling (ODM) library for MongoDB, used to define schemas, enforce validation, and manage database operations from within the Node.js application.
\end{itemize}

\subsubsection{Third-Party Platforms and Services}
\begin{itemize}
    \item \textbf{Cloudinary} -- Cloud-based media management platform used for image and video upload, transformation, and optimized delivery.
    \item \textbf{eSewa} -- Nepali digital payment gateway integrated to process NPR-based course purchases.
    \item \textbf{Stream} -- Real-time messaging and video infrastructure provider used for live class streaming and in-platform chat.
    \item \textbf{Hugging Face} -- AI model hosting platform whose Inference API was used for natural language processing tasks related to course metadata generation.
\end{itemize}

\subsection{Implementation Details of Modules}

\subsubsection{Authentication and Authorization Module}

This module is responsible for managing user identity, session security, and access control across all platform roles.

\textbf{Key Classes and Functions:}
\begin{itemize}
    \item \texttt{registerUser(req, res)} -- Accepts user registration data, validates input fields, hashes the password using \texttt{bcrypt.hash()}, and persists the new user document to MongoDB.
    \item \texttt{loginUser(req, res)} -- Verifies credentials against the stored hash using \texttt{bcrypt.compare()}, then generates and returns a signed \textbf{JWT} access token upon successful authentication.
    \item \texttt{verifyToken(req, res, next)} -- Middleware function that extracts and validates the JWT from the \texttt{Authorization} header on protected routes. Attaches the decoded user payload to \texttt{req.user} and calls \texttt{next()}.
    \item \texttt{authorizeRole(...roles)} -- Higher-order middleware factory that accepts an array of permitted roles and returns a middleware that compares \texttt{req.user.role} against the allowed roles, rejecting unauthorized requests with \texttt{HTTP 403}.
\end{itemize}

\subsubsection{Course Management Module}

This module provides CRUD (Create, Read, Update, Delete) capabilities for course content, coupled with AI-assisted metadata generation.

\textbf{Key Classes and Functions:}
\begin{itemize}
    \item \texttt{createCourse(req, res)} -- Accepts course data from an authenticated Instructor, uploads associated media to \textbf{Cloudinary} via the SDK, and persists the course document with the returned secure media URLs.
    \item \texttt{generateMetadata(title)} -- Sends the course title as a prompt to the \textbf{Hugging Face Inference API} and returns AI-generated descriptions and keyword tags to pre-populate the course creation form.
    \item \texttt{getCourses(req, res)} -- Retrieves a paginated and optionally filtered list of courses from MongoDB, supporting query parameters for category, price range, and keyword search.
    \item \texttt{updateCourse(req, res)} -- Validates ownership (instructor or admin), updates specified fields of an existing course document using MongoDB's \texttt{\$set} operator.
    \item \texttt{deleteCourse(req, res)} -- Soft-deletes or permanently removes a course document and its associated media assets from Cloudinary.
\end{itemize}

\subsubsection{Content Delivery Module}

This module manages the delivery of learning content to enrolled students through role-specific media players.

\textbf{Key Components:}
\begin{itemize}
    \item \textbf{VideoPlayer Component} -- A React component that renders a Cloudinary-hosted video stream. It tracks playback progress and reports completion events to the backend.
    \item \textbf{QuizPlayer Component} -- Renders a sequence of multiple-choice or short-answer questions fetched from the API. On submission, it calculates the score client-side and sends results to the \texttt{submitQuizAttempt()} endpoint.
    \item \textbf{AssignmentPlayer Component} -- Renders assignment instructions and provides a file upload or rich-text submission interface, dispatching the submission to the \texttt{submitAssignment()} endpoint.
    \item \texttt{trackProgress(userId, courseId, lessonId)} -- Backend function that upserts a \textit{Progress} document in MongoDB to record lesson completion status, driving the student dashboard progress indicators.
\end{itemize}

\subsubsection{Assessment and Gamification Module}

This module handles quiz authoring, assignment grading, and the automated badge award system.

\textbf{Key Classes and Functions:}
\begin{itemize}
    \item \texttt{createQuiz(req, res)} -- Accepts an array of question objects from an Instructor, validates structure, and stores the quiz document linked to a specific course lesson.
    \item \texttt{submitQuizAttempt(req, res)} -- Receives a student's answer payload, evaluates correctness against stored answers, computes a percentage score, persists the attempt results, and triggers the badge evaluation pipeline.
    \item \texttt{submitAssignment(req, res)} -- Stores the student's submitted file URL or text content, marks the assignment as \textit{pending review}, and notifies the instructor.
    \item \texttt{evaluateBadges(userId, courseId)} -- Asynchronous function invoked post-assessment. It queries the student's cumulative progress, compares it against predefined badge thresholds, and calls \texttt{awardBadge()} for each newly unlocked badge.
    \item \texttt{awardBadge(userId, badgeType)} -- Creates and persists a \textit{Badge} document linked to the user, making it visible on the student's profile and leaderboard.
\end{itemize}

\subsubsection{E-Commerce and Payment Module}

This module manages the full course purchase lifecycle from cart management through to payment confirmation.

\textbf{Key Classes and Functions:}
\begin{itemize}
    \item \texttt{addToCart(req, res)} -- Adds a specified course to the authenticated user's cart, checking for duplicate entries and validating course availability.
    \item \texttt{applyCoupon(req, res)} -- Validates a coupon code against the \textit{Coupon} collection, checks expiry and usage limits, and returns the discounted total price.
    \item \texttt{initiatePayment(req, res)} -- Constructs and signs the payment request payload and redirects the client to the \textbf{eSewa} payment gateway.
    \item \texttt{verifyPayment(req, res)} -- Handles the callback from eSewa, verifies the transaction signature and status, and upon success, creates an \textit{Enrollment} document granting the student access to the purchased course.
\end{itemize}

\subsubsection{Live Communication Module}

This module integrates real-time communication features into the platform using the Stream SDK.

\textbf{Key Components and Functions:}
\begin{itemize}
    \item \texttt{createStreamToken(userId)} -- Backend function that uses the Stream SDK's server-side client to generate a user-scoped authentication token, returned to the frontend for SDK initialization.
    \item \textbf{LiveStreamRoom Component} -- A React component wrapping the Stream Video SDK that renders the instructor's outgoing video feed and student viewer interface during a live class session.
    \item \textbf{ChatWindow Component} -- A React component integrating the Stream Chat SDK to provide a real-time, scrollable message feed within a live class channel, supporting message send, receive, and display.
\end{itemize}

\section{Result Analysis}

The testing phase yielded strong overall results, confirming that the core functional requirements of the NEXL platform have been successfully met. The following key observations were drawn from the test outcomes:

\begin{itemize}
    \item \textbf{Authentication and Authorization:} All authentication and role-based access control test cases passed successfully. The JWT-based session management and \texttt{bcrypt} password hashing performed as expected, with no unauthorized access breaches detected.

    \item \textbf{Course Management and AI Integration:} The course CRUD operations and Cloudinary media pipeline functioned correctly across all tested scenarios. The Hugging Face AI metadata generation returned contextually relevant descriptions and tags, though response latency was observed to vary between 1.5 and 4 seconds depending on server load -- an area targeted for optimization.

    \item \textbf{Assessment and Gamification:} The quiz and assignment submission workflows operated correctly end-to-end. The automated badge award system accurately identified threshold milestones and created badge records without manual intervention.

    \item \textbf{E-Commerce and Payments:} The eSewa payment gateway integration successfully processed test transactions in the NPR currency. Both success and failure callback scenarios were handled gracefully, with enrollment correctly granted only on confirmed payment.

    \item \textbf{Live Communication:} The Stream SDK integration delivered stable video streaming and real-time chat performance during testing sessions. No significant latency or message delivery failures were observed under standard test conditions.

    \item \textbf{Pending Optimizations:} Two system test cases (ST-09 and ST-10) remain in progress. Mobile viewport refinements are underway to resolve minor layout inconsistencies on smaller screen sizes. Performance under concurrent load is being addressed through database query indexing and API response caching strategies.

    \item \textbf{Overall Test Pass Rate:} Of the 27 test cases executed (15 unit + 12 system), \textbf{25 passed} and \textbf{2 are in progress}, yielding a current pass rate of approximately \textbf{92.6\%}. The remaining cases are expected to be resolved upon completion of the performance and cross-platform refinement sprint.
\end{itemize}
